# Page Check

HTML 파일 하나를 5가지 기본 품질 관점에서 점검하고, 문제의 심각도를 3단계로 분류해 보고하는 스킬이다.

## 언제 쓰는가

사용자가 "페이지 점검", "page check"라고 말하거나, 방금 만든/수정한 HTML 페이지가 기본적인 실수 없이 잘 작성됐는지 확인하고 싶어할 때 사용한다. 파일을 명시하지 않으면 최근 대화에서 다루던 HTML 파일이나 프로젝트 루트의 `index.html`을 대상으로 삼되, 애매하면 사용자에게 어떤 파일을 점검할지 확인한다.

## 점검 절차

### 1. 원시 진단 실행

title, viewport, 인코딩, img alt, 내부 링크 5가지는 정규식/눈대중보다 파서로 확인하는 게 훨씬 정확하다. 반드시 번들된 스크립트를 먼저 실행해 원시 데이터를 얻는다:

```bash
python "$CLAUDE_PLUGIN_ROOT/skills/page-check/scripts/check_page.py" <html_file>
```

스크립트는 JSON을 출력한다. 이 JSON은 "사실"만 담고 있고 심각도는 매기지 않는다 — 심각도 분류는 아래 표를 따라 이 스킬을 실행하는 모델이 직접 판단한다.

### 2. 심각도 분류

스크립트 출력을 아래 표에 따라 분류한다. 표에 없는 애매한 사례(예: alt는 있지만 "image123.png"처럼 의미 없는 텍스트, title은 있지만 "Untitled Document"처럼 기본값 그대로인 경우)는 🟢 제안으로 내려서, 페이지는 정상 동작하지만 더 다듬을 여지가 있다는 뉘앙스로 보고한다.

| 항목 | 판정 기준 | 등급 | 이유 |
|---|---|---|---|
| title | `title.present`가 false, 또는 `title.empty`가 true | 🔴 심각 | 브라우저 탭/북마크/검색결과에 페이지를 식별할 수 없음 |
| 내부 링크 | `links.broken`에 항목 존재 | 🔴 심각 | 클릭 시 실제로 깨지는 사용자 경험 문제 |
| 한글 인코딩 | `charset.declared_is_utf8`가 false, 또는 `charset.file_decodes_as_utf8`가 false | 🔴 심각 | 한글이 실제로 깨져 보일 수 있는 직접 원인 |
| 이미지 alt | `images.missing_alt`가 비어있지 않음 | 🟡 주의 | 스크린리더 접근성과 SEO 저하, 페이지 자체는 동작함 |
| 모바일 viewport | `viewport.present`가 false | 🟡 주의 | 모바일에서 레이아웃이 축소되어 보이지만 접근은 가능함 |

각 항목이 판정 기준에 걸리지 않으면 통과이며, 특별히 다듬을 부분이 보이지 않는 한 보고서에 🟢로 표시한다.

### 3. 보고서 작성

아래 템플릿을 그대로 사용해 한국어로 보고한다. 발견 사항이 없는 카테고리는 생략하지 말고 "해당 없음"으로 남겨 5가지를 모두 점검했다는 것을 보여준다. `images.missing_alt`의 `src`가 data URI처럼 너무 길면 앞 30자 정도로 줄여서 `...(생략)`을 붙인다.

```markdown
## 📄 페이지 점검 결과 — <파일명>

| 항목 | 결과 |
|---|---|
| title 유무 | 🔴/🟡/🟢 <한 줄 설명> |
| 내부 링크 | 🔴/🟡/🟢 <한 줄 설명> |
| 이미지 alt | 🔴/🟡/🟢 <한 줄 설명> |
| 모바일 viewport | 🔴/🟡/🟢 <한 줄 설명> |
| 한글 인코딩(UTF-8) | 🔴/🟡/🟢 <한 줄 설명> |

### 🔴 심각 (n건)
- <구체적 위치와 수정 방법>

### 🟡 주의 (n건)
- <구체적 위치와 수정 방법>

### 🟢 제안 (n건)
- <구체적 위치와 개선 아이디어, 또는 "특별히 없음">
```

문제마다 "어디가 왜 문제인지"와 "어떻게 고치는지"를 한 줄로 붙인다. 예를 들어 title이 없으면 `<head>` 안에 `<title>페이지 제목</title>`을 추가하라고, viewport가 없으면 `<meta name="viewport" content="width=device-width, initial-scale=1">`를 `<head>`에 추가하라고 구체적으로 알려준다.

모든 항목이 🟢인 경우에도 표는 그대로 보여주고, "5가지 항목 모두 이상 없습니다" 같은 한 줄 요약을 위에 덧붙인다.

## 참고

- 이 스킬은 로컬 파일(상대 경로) 링크만 깨짐 여부를 검사한다. `http://`, `https://`, `mailto:`, `tel:` 등 외부 링크는 네트워크 접근 없이는 검증할 수 없으므로 대상에서 제외하고, 필요하면 보고서에 "외부 링크는 점검 대상 아님"이라고 한 줄 덧붙인다.
- 스크립트가 없거나 Python 실행이 불가능한 환경이면, 같은 5가지 기준을 사람이 직접 파일을 읽어 눈으로 확인하되 위 심각도 표는 동일하게 적용한다.
